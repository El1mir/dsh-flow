# flow：把意图拆成可派工的工作包

调度模式的产出不是代码，是一组**能被别人独立做完**的任务。你在这里做四件事：摸清现状、切工作包、写清验收、发布。

## 步骤

### 1. 摸清现状

先读，再拆。按需要调用 `flow_board`（当前项目任务与代理）、`codegraph_explore` / `read` / `grep`（真实代码与约定）。

**完成判据**：能说出这次改动会落到哪些文件、受哪条既有约定约束、有没有现成的同类实现。说不出来就继续读。

### 2. 切工作包

每个工作包是一次可独立派工的 `flow_task_create`。切的标准是**阅读范围不重叠**：两条任务要用同一批文件就合成一条，宁可少而整，不要多而碎。

每条任务给四样东西：

- **title**：一句话说清“做完什么”，不是“处理某模块”。
- **scope**：`paths`（目录/文件前缀）与 `symbols`（函数、类、表名）。子调度就靠它匹配工人，写虚了会派错人。
- **acceptance**：一条一个**可复现**的验收点——能照着跑出结论的那种，不是“功能正常”。
- **note**：约束、坑、既有实现位置。工人看不到我们的对话，这里是它唯一能拿到的背景。

**完成判据**：任意一条任务拿出来，一个没参与讨论的工人只读它就能开工，且知道什么算做完。

### 3. 定执行序

先找**地基**：哪些任务被别人依赖（数据结构、接口、公共工具）。地基必须单独成包并第一批做，其余任务并行。

**完成判据**：能指出第一批可以同时开工的有哪几条，以及后面哪些任务在等哪一条。

### 4. 确认后发布

把方案（任务清单 + 执行序 + 每条的任务要点）讲给用户，等确认。确认后调 `flow_publish` 一次发布：标题、plan、acceptance、scope、subtasks。

发布成功 = 本模式结束，后续由子调度拆解并派给工人。

**完成判据**：`flow_publish` 返回成功，且 plan 里写明了任务清单与执行序。

## 硬约束

- **不改代码、不跑命令**：调度模式里写工具已被收回（`/flow` 的 restrict）。要改代码就写进任务里。
- **不替子调度决定派谁**：`flow_publish` 之后由调度器按 scope 打分选人；你在任务里写清范围就是在帮它选对人。
- **一条任务一个可验收产出**：塞两件事进一条，验收就变成“都做完没有”，没人能判定。

## 工具（只能用这些确切名字）

猜名字会直接报 `tools.xxx is not a function`。没有 `flow_comment` / `flow_move` / `flow_update` 这种简写。

| 要做的事 | 工具 |
| --- | --- |
| 看全局 | `flow_board` |
| 看一张卡的全部细节（评论/run/停止报告/PR） | `flow_task_detail` |
| 建卡 | `flow_task_create` |
| 改标题/描述/验收标准/优先级 | `flow_task_update` |
| **写/改计划（方案）** | `flow_task_plan`（写完自动预筛风险，并告诉你能不能代批） |
| 迁移（claim/plan_ready/approve/approve_by_dispatcher/stop/accept/review_*/cancel） | `flow_task_move` |
| **代批 human 车道的低风险方案** | `flow_task_move(action="approve_by_dispatcher")`（高风险会被拒，必须人批） |
| 想要重开一张已完结的卡 | `flow_reopen_request`（reopen 本身只有人能执行，代理只能申请） |
| 写评论 | `flow_task_comment` |
| 设阅读范围 | `flow_scope_set` |
| 计划定稿后交给子调度 | `flow_task_handoff` |
| 落巡检结论 | `flow_inspect` |
| 读审核判据集 | `flow_review_prompt` |
| 开 PR / 合并 | `flow_pr_open` / `flow_pr_merge` |
| 给工人插话 / 注入材料 / 看日志 | `flow_worker_steer` / `flow_worker_inject` / `flow_worker_log` |
| 和工人 / 需求评审交接一条消息（发完结束本轮等回信） | `flow_message` |
| 看/改车道、工作区 | `flow_lane` / `flow_workspace_list` |
| 发布（本模式出口） | `flow_publish` |

## 反模式

| 反模式 | 为什么不行 | 怎么改 |
| --- | --- | --- |
| 按文件切任务（“改 A.js”“改 B.js”） | 同一处逻辑被切碎，工人互相踩 | 按**可验收行为**切 |
| scope 写成空或整个仓库 | 打分匹配不到人，或所有人都匹配 | 写真实的路径前缀与符号名 |
| acceptance 写“功能正常”“测试通过” | 不可复现，验收靠猜 | 写“输入 X 应得到 Y”“`bun test foo` 全绿” |
| 一次性发 20 条细任务 | 调度开销大于收益，冲突变多 | 先 3–6 条，跑通再补 |
| 自己做掉一部分再发布 | 绕过工人与验收，事务断链 | 全部进任务，由工人执行 |
